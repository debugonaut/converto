# Converto CLI audit and repair report

2026-11-01, Asia/Kolkata. Scope: establish the CLI before GUI work, preserve the landing page, terminal layout and ASCII artwork, audit the 25 catalog commands, repair reproduced faults, and expose the limits of the evidence.

## Result and release status

The repaired macOS arm64 CLI passes **321 acceptance checks with all networking denied**, **78 repository tests**, **12 real controlling-PTY scenarios**, and the Node launcher regression. All 25 slash commands execute. Every one of the 21 registered source extensions goes through both explicit conversion and the bare dropped-file action menu. The format matrix contains **114 distinct source/target pairs**.

The self-contained profile reports **283 passes, 38 expected unsupported helper-dependent cases, zero failures**. Those unsupported cases test truthful rejection; they are not successful conversions. The full profile uses installed local LibreOfficeDev (an alpha build) and cwebp; stable helper versions still need the prepared native CI run. No helper is downloaded by a running conversion.

This is a verified local macOS build, **not a certification of Windows/Linux releases or every possible file**. Their native CI jobs are prepared but have not run here. Actual Finder/Explorer/Nautilus gestures in desktop terminal apps, PDF/A conformance, and broad Office layout fidelity remain release gates. The repository URL is still needed to connect real release/download targets; this workspace has no Git metadata.

## What was repaired

1. **Terminal hangs and input loss.** Replaced synchronous byte/line readers with one async stdin owner so OS interrupts can run. Ctrl+D exits, Ctrl+C restores the terminal, CRLF does not become a second command, and all prompt paths share buffered input. Bracketed paste is enabled and retains embedded newlines until its closing marker. Removed the 64 KiB premature-paste execution behavior. A drop or `/exit` entered at the post-action prompt no longer loses its first byte.
2. **Path parsing.** Isolated terminal-text parsing from already-tokenized argv. Preserved escaped apostrophes, quotes, parentheses, brackets, ampersands, dollar signs, Unicode, tabs, drive roots, UNC paths and PowerShell quoting. File URIs decode correctly; remote hosts and malformed URI escapes are rejected. Literal `00~`/`01~` inside a real filename are preserved.
3. **Merges.** Replaced file-family dispatch based on the first file with one shared ordered PDF/image merge. Mixed drops no longer silently omit PDFs or send images to the PDF parser. Each image is processed separately; intermediate PDFs are removed. All-PDF merging avoids duplicate pre-parsing.
4. **Truthful output formats.** WebP output uses local cwebp or fails clearly. GIF and ICO outputs use their encoders instead of renamed PNG bytes. PPTX/PPT/ODP image targets render a temporary PDF into an actual PNG/JPG. First-page/first-slide behavior is disclosed; `pdf2img` exports every page.
5. **Image pages and resolution.** Worked around the image dependency's default TIFF behavior to preserve every TIFF page. Animated GIF-to-PDF retains frames. ICO entries are treated as alternative resolutions of one icon, selecting the largest, rather than generating multiple PDF pages. EXIF orientation is honored.
6. **Office parsing and helper isolation.** Validate OLE/ZIP/XML structure before invoking LibreOffice. Use private input/output directories and a private profile, check generated output instead of stale files, and clean staging. Legacy XLS now uses the appropriate local engine. A valid XLSX without a styles part is normalized for the parser. PPTX text fallback follows relationship order, including reordered slides.
7. **Spreadsheet content.** LF/CRLF CSVs, quoted fields and multiline cells are exercised. PDF output includes every XLSX worksheet; CSV's first-sheet behavior is disclosed.
8. **Output safety.** Honor explicit file/directory outputs and same-format copy requests. Stage beside the destination and rename after successful work. A failed write preserves an existing destination. Explicit file extensions must match the requested format. PDF image export no longer writes to Documents before honoring `-o`; its first filename cannot overwrite page 2.
9. **Validation and exit status.** Await command futures so errors reach the runner. Reject bad quality, DPI, finite-value, crop, angle and page-selection inputs rather than silently substituting defaults. Too-small split sizes fail. Batch failures return nonzero. Unknown or incomplete slash options fail clearly.
10. **Native page-number placement.** Visual QA found the dependency's corner fields were not reaching the native engine. An isolated streaming adapter supplies the expected `posFields` wire value. The dependency is pinned to 5.0.1 while this adapter is needed. A bounding-box regression now checks bottom-right placement.
11. **Efficiency and storage.** Embed original JPEG bytes into PDF without decoding/re-encoding. Pass decoded images directly to PDF generation, avoiding a PNG encode/decode cycle. Compression retains original bytes if the result would grow. Typo assistance no longer recursively walks the repository. Local history is capped and can be disabled.
12. **CLI shipping path.** The launcher selects only the exact OS/architecture; Windows uses the correct bundle directory, and startup errors propagate. Source tests no longer silently fall back to a stale macOS executable. CI builds/tests/packages native CLI bundles instead of incomplete GUI scaffolds. Unit converter outputs are isolated in temporary directories. Windows open-file dispatch no longer routes filenames through `cmd /c start`.

Windows text encoding and Unicode data loss were also repaired. TXT/CSV accept UTF-8 and BOM-marked UTF-16 LE/BE, preserve bytes on same-format TXT copies, and reject malformed surrogate pairs. Text that the built-in PDF fonts cannot represent is routed through installed local LibreOffice or rejected clearly, rather than silently dropping glyphs. DOCX/PPTX and spreadsheet fallbacks apply the same font guard. These cases include Chinese text; arbitrary fonts and complex shaping are not certified.

The main implementation boundaries are `lib/core/terminal/terminal_input.dart`, `input_parser.dart`, `lib/services/file_operations.dart`, `office_bridge.dart`, `storage_service.dart`, and the isolated `pdf/page_number_bridge.dart`. The existing UI and logo code were preserved.

Checks go beyond a successful exit: magic/signature decoding, image dimensions, visible-colour comparisons for PNG/TIFF outputs, PDF page counts and geometry, extracted text and order, Office ZIP/XML structure, known document/sheet/slide text and nonblank presentation rasters, independent password authentication and redaction extraction. The audit retains the raw difference and normalizes chroma smoothing for the colour comparison. It does not claim identical pixels across JPEG decoder implementations.

## Drag-and-drop and terminal coverage

The 12 controlling-PTY scenarios exercise normal exit; Ctrl+D; Ctrl+C; bracketed commands; CRLF; multiline local file-URI drops; new commands at post-action prompts after single and multiple drops; Ctrl+C at a source prompt; unknown escape sequences and empty paste; a paste exceeding 64 KiB; and a bare-file action menu followed by 25 repeated conversions in the same session. Terminal echo and canonical input restoration are checked. All 12 pass. The initial 10-case baseline had four reproduced failures: Ctrl+D hang, Ctrl+C terminal-state restoration, and two multiline-paste scenarios.

Additional acceptance cases cover escaped punctuation, apostrophes and quotes, Unicode filenames, literal marker-like names, file-URI decoding, multiple files, repeated inputs, both mixed-family orders, folder snapshots, hidden/unsupported files, and a symlink cycle. Missing companions are rejected. Corrupt inputs, missing paths, output mismatches, existing destinations, malformed flags, invalid ranges and EOF are exercised.

Windows drive/UNC/PowerShell and Linux XDND strings are parser tests on macOS. The PTY is a real native macOS terminal interface, but it does not constitute an actual Finder gesture in Terminal.app/iTerm, a Windows ConPTY/Explorer test, or a Linux desktop file-manager test.

## Release gates and remaining limits

1. **Run native CI on Windows, Linux and intended CPU architectures.** Workflow files are ready; they were not remotely executed because this workspace has no Git metadata/confirmed repository. Windows ConPTY currently produces an explicit skipped terminal-test record rather than pretending POSIX PTY coverage is Windows coverage.
2. **Wire real distribution URLs.** Existing landing-page installer links point to placeholder GitHub paths and do not match the new CLI ZIP artifacts. No release was published, signed or notarized. The landing page was left visually unchanged.
3. **State helper requirements accurately.** The standalone profile deliberately rejects 38 helper-dependent or unsupported-font cases (including repeated conversion/menu paths). An all-formats self-contained claim requires separately packaging the missing codecs or choosing a larger Office runtime. The core does not auto-download them.
4. **Validate PDF/A independently before archival claims.** Creating a readable file with PDF/A metadata is not proof of conformance. No veraPDF validation was performed.
5. **Retain fidelity qualifications.** Native redaction is span-based and can remove adjacent words on the same line; scanned pages require OCR, which is not implemented. DOCX/PPTX fallback omits graphics/original layout. Unicode font/shaping, complex Office charts, formulas, forms, signatures and arbitrary PDF object structures are not exhaustively certified.
6. **Keep resource and concurrency limits honest.** No disk-full, power-loss, terabyte, 32-bit, or simultaneous-default-basename multi-process test is certified. One invocation processes batches sequentially; simultaneous processes should use separate output paths. Crop/resize options in the image service are not all exposed as CLI flags. The provided tests are a bounded matrix, not every possible edge case.
