# Linux desktop app verification

Converto now has a Linux x86_64 GUI developer preview, using the same 19 file
tools, previews, output naming and transactional saves as the desktop workflow.
The existing layout, logo and offline processing model are preserved.

Verified source: `b8f8c3bae21db1241d7096c569c7feab3cf427d7`.
[All three OS jobs passed](https://github.com/debugonaut/converto/actions/runs/41321201386)
on 2026-11-01, including native Mac/Windows regressions and Ubuntu 22.04 Linux.

| `Converto-Linux-amd64.deb` | 15.39 MiB (16,137,424 bytes) | `c4debfc6682e81c0753ca0e7a38adabd274a1717ebc699f805c5643094258a66` |

The portable app occupies **54.41 MiB** (57,050,795 bytes).
It contains the Flutter/AOT/ICU runtime, desktop-drop plugin, PDF engine and
licenses. GTK, fonts and graphics drivers come from the operating system.
There is no bundled browser, Flutter SDK, runtime downloader or FUSE requirement.
The Debian package derives versioned system dependencies with `dpkg-shlibdeps`;
the maximum required GLIBC symbol version is **2.35**.
The verified baseline is **Ubuntu 22.04 x86_64**. Other distributions and ARM
builds are not claimed as tested.

Portable: extract the entire tar.gz and run `Converto/converto`; keep `lib/` and
`data/` beside it. Debian: install the .deb through your package manager. Its
application-menu entry launches `/opt/converto/converto`; the optional
`converto-gui` terminal command leaves the CLI's `converto` name separate.
Missing system dependencies may need installation during setup. Processing
remains local and offline. Optional Office/WebP helpers are not bundled or
silently downloaded.

## Integration and repairs

- Added the native GTK runner, Linux platform typography/shortcuts and desktop
  package metadata while retaining the shared GUI workflows.
- Replaced Linux's external zenity/kdialog discovery with a GTK file/folder
  chooser channel. It selects local files, supports multiple selection and
  returns cancellation without triggering processing. Other OS pickers remain
  on their existing native implementation.
- Preserved executable modes, checked all six ELF code files as x86_64, checked
  complete archive contents after extraction, and compared the Debian payload.
- Launched both relocated packages from a separate working directory under
  Xvfb/software GL, with isolated user state, no SDK environment and only system
  PATH. Both reached their native first frame, cancelled both chooser types
  through the Dart/GTK bridge and completed a real bundled PDF operation.
- Verified watermarking through changed rendered page pixels and preserved
  source text. The engine's text extractor does not include watermark graphics;
  text matching alone is not used as evidence that the watermark appeared.
- Fixed an older LibreOffice CSV import encoding bug exposed by this baseline.
  CSV inputs are normalized only in private staging and imported explicitly as
  UTF-8. UTF-8 Chinese and BOM-marked UTF-16LE/BE CSV-to-PDF cases now pass;
  original file bytes remain unchanged. The import options follow
  [LibreOffice's CSV documentation](https://help.libreoffice.org/latest/en-GB/text/shared/guide/csv_params.html).

Native packaging follows [Flutter's Linux build guidance](https://docs.flutter.dev/platform-integration/linux/building),
including its complete bundle and system-library requirements.

## Reproduction and coverage boundary

CI builds with Flutter stable, installs the Linux GTK/build tools, runs the
shared source/CLI/GUI suites, then executes `python tool/package_linux.py`.
`linux-app-x64` contains both packages; `linux-app-audit` contains checksums,
dependency listings, startup logs and GUI analytics. The `cli-Linux` artifact
contains full/standalone/terminal case results. Local copies are under
`build/audit/linux-app/ci-final/` and `build/audit/linux-app/cli-final/`.

The localhost Linux buttons serve these verified inner packages directly. No
public hosting or GitHub Release was created. Build archives remain ignored by
git and the download files share their verified immutable local artifact inode
to avoid duplicate storage.

**Manual coverage remains pending:** file acceptance and folder selection in a
human desktop session, Nautilus/Dolphin/Thunar drag/drop, GNOME/KDE,
X11/Wayland, hardware GPUs, display scaling, package-manager install/uninstall,
and representative very large files. Xvfb and mocked drop events do not stand
in for those checks. Instructions and pending results are in
`build/manual-testing/linux/GUIDE.md` and `RESULTS.md`.

No peak-RAM or large-file throughput claim is inferred from these small fixtures.
Processing has no artificial file-size quota, but available memory/disk, codec
limits and existing helper timeouts still apply.
