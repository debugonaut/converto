# macOS app implementation and verification — 2026-11-01

The approved desktop tool hub is implemented as a native Flutter Mac app. This report covers the **19 GUI file tools**; the six terminal utility operations become navigation, settings, help and app lifecycle rather than extra file-tool cards. The previous 25-command/114-pair CLI audit remains separate.

## Checks completed

- All 19 GUI tools passed the exact shared executor used by the background worker. **32/32 acceptance checks passed**, including expected failures. The same suite passed with macOS networking denied using `sandbox-exec`.
- Independent PyMuPDF/Pillow inspection passed for generated PDFs/images: ordering, page counts, crop/rotation geometry, watermark/numbers, encryption/unlock, redaction text removal and image signatures.
- Flutter tests exercise search, empty filters, all 19 empty/selected workspaces, 780/1180 px layouts, rapid repeated drop callbacks, a 10,000-result lazy list, real isolate execution, immediate cancellation and batch name collisions/source attribution.
- Static analysis passes. Full CLI regressions run in the existing three-OS CI matrix; no Windows/Linux GUI packaging or native UI interaction is claimed.
- The initial [native CI build](https://github.com/debugonaut/converto/actions/runs/41285809553) passed all three jobs, built both Mac executable architectures, packaged notices/native frameworks, and verified ad-hoc signing. The downloaded app also passed `codesign --verify --deep --strict` on macOS 15.7.4 arm64. The executable declares macOS 13.0 minimum for both architectures.

## Integration and resource choices

- A single typed catalog routes tools to the existing local engines; the obsolete GUI conversion coordinator and duplicate job model were removed.
- Drops/picker results only select files. Intake preserves OS-tokenized names, serializes overlapping drop batches, deduplicates paths, rejects links and unsupported inputs, and scans folders shallowly without recursive symlink loops.
- CPU/native processing runs in a worker isolate. Files process sequentially; JPEG-to-PDF retains the existing direct-embedding fast path.
- Private job staging is on the output filesystem. Successful batches publish with unique names using rename, keeping source files and existing outputs intact. Failed/cancelled jobs clean up staging.
- Result widgets are lazy and bounded; image previews request a bounded decode width. This is a UI rendering optimization, not a file-size limit.
- History writes once per completed batch, retains up to 1,000 metadata records, attributes each output to its source, and stores no passwords. Large page exports stat only the newest history entries. Users can disable/clear local history.
- The app reuses the engine; it does not bundle a second CLI executable, helper installer, remote font, telemetry client or network service. Finder launches discover standard local Homebrew helper paths without needing a shell.
- The first universal Mac package measured **99,867,239 bytes (~95.2 MiB)** excluding symlink aliases and **41,844,267 bytes (~39.9 MiB)** zipped. This includes the Flutter runtime and local native PDF backend; optional helpers are separate. Final packages produce exact measurements in their `package.json`.

## Explicitly pending

**Native window, native file picker, Finder-to-app drag and drop, keyboard focus and accessibility interaction were not manually exercised.** Computer Use reported missing permissions, and the user requested finishing with build/automated checks. Flutter callback/widget coverage and automated renders do not replace those native interaction checks.

The app is an ad-hoc signed developer preview, not an Apple Developer ID signed/notarized public release. Intel is compiled into the universal bundle but was not executed on an Intel Mac. macOS 13/14 and other Mac hardware remain compatibility validation targets.

No multi-gigabyte, low-disk, power-loss, forced-process-termination or sustained-memory certification was performed. No arbitrary PDF text/layout editor, OCR or signing feature is represented by the 19 approved GUI tools. PDF/A independent conformance and redaction visual review remain necessary for sensitive archival/sharing workflows.

## Reproduce

```sh
flutter pub get
flutter analyze --no-pub
dart tool/verify_cli.dart
dart run tool/audit_gui.dart
flutter build macos --release
python3 tool/package_macos.py
```

On macOS, the runtime network-deny check is `sandbox-exec -p '(version 1)(allow default)(deny network*)' dart run tool/audit_gui.dart`. Build/dependency setup can use networking; the local test inputs and runtime operations do not.

Automated Flutter renders can be regenerated with `flutter test tool/render_gui_test.dart`; this utility uses local system/SDK fonts and writes `build/audit/gui-renders/`. These are offscreen widget renders, not native screenshots. Raw executor metrics are in [executor-results.json](2026-11-01-macos/executor-results.json).
